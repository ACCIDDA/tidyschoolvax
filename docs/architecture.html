§1

What this package does

tidyschoolvax is the upstream preprocessing stage of the ACCIDDA measles pipeline. Each state publishes kindergarten MMR vaccination counts under whatever school name and formatting its own systems use, in files that arrive one school-year at a time. Before that data can feed a coverage model, every record has to be resolved to one physical school — the same school, whether it's called “Robert E. Lee Elementary” in a 2019 file or “Northside Elementary” in a 2024 one.

The package does this by cross-matching three kinds of source against each other — GreatSchools.org, the state Department of Education, and the raw kindergarten files — using a cascade of increasingly loose signals: first an exact Google place_id, then address, then ZIP, then city, then county. Everything downstream (data-quality checks, the model's input tables) is built on top of the resulting school key.

§3

Why reordering the geocoding step matters

Matching has always run on fuzzy string distance — Jaro-Winkler, soundex, cosine, and three other metrics computed in C++ (match_schools_batch_cpp()), scored and tie-broken in R (match_schools_names()). That works well for typos and formatting drift, but a genuine rename produces two name strings with nothing in common to measure. Fuzzy matching either leaves the new name unmatched, or — worse — links it to whichever other school in the county happens to look closest.

A Google Place ID doesn't have that problem: it identifies the physical location, not the label on the sign. Moving geocoding from the last step to the first means every source — GreatSchools, DOE, and the kindergarten file itself, where an address is available — can carry a place_id into the matching stage, where it becomes Pass 0, an exact join that runs before any string comparison at all.

§6

Design decisions worth knowing

Identity before geometry before text

The cascade always tries the strongest signal first: an exact place_id, then structural signals (address, ZIP, district), then plain county-level fuzzy matching as the last resort. Each pass only ever sees what the passes above it left unmatched.

One cache, read from three places

geocoded_cache.rds and status_cache.rds are written once but read by both the early identity-resolution step and the late enrichment step — moving geocoding earlier didn't roughly double the API calls, because the second read mostly hits cache. Filenames are single-sourced in .geocoding_cache_paths() so the two writers and clear_geocoding_cache() can't drift apart.

Deprecate in place, don't delete

The legacy base-R DQA stack overlaps with final_format_utils.R but has diverged contracts — different error handling, a fixed column list versus a parameterized one. Rather than force a merge that would silently change behavior, it's documented as superseded and left alone.

Renames are logged, not just fixed

Every school pair reconciled through the place_id pass — or matched via a Google name variant a source hadn't caught up to yet — is written to school_renames_detected.csv, sorted so identity-based matches surface first. The fix is auditable, not silent.
